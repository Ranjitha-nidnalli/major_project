# Krishi Mitra

Kannada RAG chatbot for sugarcane farmers in Karnataka. Safety-critical domain: a wrong
pesticide dose can destroy a crop or harm a person. Refusing is always better than guessing.

Read `ARCHITECTURE.md` first. It is the source of truth for design decisions and the
phase roadmap. This file holds current facts and working rules only.

## Current stack (as of Sep 2026)
- Backend: FastAPI (`backend/main.py`). Frontend: Next.js (`frontend/`).
- Embeddings: BAAI/bge-m3 via FlagEmbedding (dense + learned sparse, NOT classical BM25).
- Vector DB: Qdrant, collection `sugarcane_knowledge`, named vectors `dense` + `sparse`.
  Docker server mode (`docker compose up -d`, see `docker-compose.yml`) is primary; local
  file mode is a documented fallback only (ARCHITECTURE.md Section 6).
- Chat history: MongoDB, db `sugarcane_chat` (also via docker-compose).
- LLM: `backend/llm_client.py`, backend chosen by `LLM_BACKEND` (default `groq`), model by
  `GENERATION_MODEL` in `backend/.env`. No hardcoded model fallback strings. Model quality
  in Kannada is UNVALIDATED. OpenRouter backend available for cross-judge evaluation.
- Reranker (bge-reranker-v2-m3) is loaded in `vector_db.py` but NOT used by `rag_service.py`
  (`ENABLE_RERANKER=false` by default -- deliberate, see ARCHITECTURE.md Section 13).
- Corpus: `sugarcanemerged3.json` at repo root. Chunk count last verified as 43 before the
  2026-09-20 chunker/vector_db.py rewrite (deterministic content-hash IDs replaced uuid4) --
  re-run `python vector_db.py` to reconfirm before citing a count. Provenance unknown.
  Contains Tamil Nadu content. Do not treat as authoritative.

## Commands
- Start services: `docker compose up -d` (Qdrant + MongoDB)
- Seed index: `cd backend && python vector_db.py`
- API: `cd backend && python main.py` (port 8000)
- Frontend: `cd frontend && npm install && npm run dev` (port 3000)
- Tests: `cd backend && pytest` (pure invariant tests, no live services needed)

## Pipeline (`rag_service.get_sugarcane_answer`)
LLM router -> embed query -> hybrid RRF top-5 (no category filter) -> abstention gate
(`services/gating.py`, dense-cosine relevance) -> LLM generation -> LLM faithfulness judge +
regex numeric check -> save to Mongo.

## Rules
- Work on a branch per phase. Small commits. Never push to `main`. Run tests before commit.
- Never commit `.env`, API keys, or raw downloaded data. Never print keys.
- Never free-generate, estimate, convert, or "fix up" doses, chemicals, or units. Numbers
  must come from a verified typed fact record. If data is missing, refuse or stop and ask.
- Never invent agricultural facts, sources, or citations.
- An LLM classification must never make a document unreachable (no hard filters from router).
- One Kannada normalisation function (`indic_preprocess.normalize_kannada`) for corpus,
  queries, and eval references.
- Do not change chunk text or chunk IDs without re-checking that every gold ID still exists.
- Eval runs write to their own directory, never append to a shared file. Record dataset
  hash, model ID, prompt version. Never report numbers computed on stale gold.
- ROUGE-L is invalid on Kannada (6/16 references score 0.000 against themselves). chrF and
  BLEU cannot detect numeric errors (a 10x overdose scores higher than a valid paraphrase).
  Never present them as quality or safety evidence on their own.
- These are HUMAN tasks. Do not automate them and present output as verified: gold labels,
  dosage verification against source documents, source selection, Kannada quality ratings.
- User-facing text is Kannada. Code, comments, identifiers are English.
- Before deleting a file, grep for imports. Move stale eval artifacts to
  `backend/eval/_archive_stale/` instead of deleting them.
- Do not make paid LLM/API calls unless explicitly told to.
