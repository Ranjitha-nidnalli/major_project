# Archived, stale eval artifacts

These files describe a corpus state that no longer exists. They are kept
here for historical reference only -- **do not read from them, and do not
report numbers computed from them.**

| File | Why it's stale |
|---|---|
| `chunks.jsonl` | Dump of a previous chunking run. IDs don't match the current corpus after chunking changes. |
| `chunk_id_map.txt` | Maps the above stale IDs. |
| `gold.jsonl` | Hand/auto-labelled gold answers keyed to the stale chunk IDs above. Zero of these IDs resolve in the current index. Labels were also auto-generated by the retriever under test (circular -- see CLAUDE.md). |
| `retrieval_results.jsonl` | Retrieval ablation output run against the stale corpus/gold. |
| `contexts.json` | Frozen per-question contexts built from the stale retrieval, used by `run_eval.py`. |
| `results.jsonl` | Generation-model comparison scored against the stale contexts/gold. |
| `refusal_results.jsonl` | Refusal-accuracy run against the stale gold. This is also the file that recorded the unanswerable price query at `search_score: 1.0` -- the specific evidence that the old confidence gate never fired (ARCHITECTURE.md Section 21). Kept for that reason, not as valid eval output. |
| `questions_UPDATED.json` | Duplicate question IDs with different text from `questions.json` -- a silent trap if used interchangeably with it. |

Regenerating a real, current eval set is Phase 2 work (ARCHITECTURE.md
Section 30: hand-labelled gold on 40-50 questions, two labellers, 10
double-labelled). Do not patch these files back into use.
